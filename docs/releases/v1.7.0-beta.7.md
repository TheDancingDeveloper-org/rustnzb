# rustnzb v1.7.0-beta.7

## Highlights

- **Failed jobs no longer leave partial files behind.** A job that fails for
  good now deletes its `incomplete/<id>` directory instead of keeping it for a
  missing-article retry that never came. Deleting history, including an
  *arr's `removeFailed` delete that keeps the History row, removes any
  leftovers. On startup the orphan sweep reclaims partials that older
  releases kept for failed jobs. A retry downloads the job again from its
  stored NZB. (#282)
- **Sonarr and Radarr stop looping on duplicates.** SABnzbd-compatible
  `addfile` and `addurl` accept a re-grab of a failed or deleted job. They
  refuse only duplicates that are still queued or already completed, and
  they answer with SABnzbd's own refusal, `{"status":true,"nzo_ids":[]}`, so
  the *arr blocklists the release instead of grabbing it again. (#283)
- **An idle NNTP close is no longer logged as an error.** When a server
  closes an idle connection, the log records a normal disconnect.

## Upgrade notes

- No database migrations in this release. Backing up `rustnzb.db` before
  upgrading is still recommended.
- After the upgrade, the first startup deletes failed jobs' partial files in
  `incomplete/`, which can free a lot of disk space.

## All changes

### Fixed

- **queue:** failed jobs' partial files are deleted on final failure, and
  deleting history removes leftovers (WI-2173, #282)
- **admission:** re-grabs of failed or deleted jobs are admitted; only queued
  or completed duplicates are refused, with SABnzbd's refusal response
  (WI-2165, #283)
- **nntp:** a server idle close is logged as a normal disconnect (WI-2166)
