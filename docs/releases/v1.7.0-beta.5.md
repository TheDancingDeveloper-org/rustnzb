# rustnzb v1.7.0-beta.5

## Highlights

- **Adding an NZB no longer freezes the web UI on large histories.** Duplicate
  detection used to scan the whole History table on every add, holding the
  database lock while it did. The lookup is now indexed, so adding a job stays
  quick however large your History gets.
- **Sonarr and Radarr "Remove Completed" keeps your History.** The job's files
  are still deleted as asked, but the History entry stays, marked with the
  client that removed it, the time and whether files were deleted. Entries
  marked this way drop out of the SABnzbd History that the *arrs poll, so they
  do not reappear. To get the old SABnzbd behaviour back, turn off **Keep
  History when an *arr removes a job** in Settings.
- **The connection pool updates live while downloading.** The panel was only
  refreshed on page load and after user actions, so it could show stale numbers
  during a download. It now refreshes with the queue.
- **The connection count shows sockets that are actually open.** It used to
  count worker slots, so it did not drop when a server closed an idle
  connection. Idle connections are now checked every 30 seconds, and a socket
  the server has closed is dropped and reconnected when there is work.
- **Paths, post-processing and network/API settings are editable in the GUI.**
  Values are validated strictly before they are saved. The data directory stays
  read-only in the GUI and is still set in the configuration file.

## Upgrade notes

- **Back up `rustnzb.db` before upgrading.** Database migrations v22 and v23
  run automatically on start. v22 adds an index for duplicate detection; v23
  adds the table that records *arr removals. Stop rustnzb, copy the database
  file, then start the new build.
- **History entries the *arrs deleted before this release are not restored.**
  Only removals made by this build keep their History entry.
- **Changed paths apply to new jobs only.** Jobs already in the queue keep the
  paths they were added with.

## All changes

### Added

- **ui:** *arr-removed History rows show a "Files removed by" badge, and
  Settings gains a **Keep History when an *arr removes a job** toggle

### Changed

- **sab:** an *arr "Remove Completed" deletes the files but keeps the History
  row, marked with the client, time and file removal. Set
  `general.keep_history_on_arr_delete = false` for the previous SABnzbd
  behaviour (default on)

### Fixed

- **db:** adding an NZB no longer scans the whole History table; duplicate
  lookups use indexes (migration v22)
- **queue:** the connection pool panel refreshes on the queue poll while
  downloading
- **dispatch:** the connection count reports open sockets rather than worker
  slots, and idle sockets the server closed are dropped
