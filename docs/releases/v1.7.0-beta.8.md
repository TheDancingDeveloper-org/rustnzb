# rustnzb v1.7.0-beta.8

> **Rollback warning.** This release rewrites `credentials.json` on first
> start: the web-login password is replaced by an Argon2id hash
> (`password_hash`). v1.7.0-beta.7 and earlier cannot read the new file. They
> treat it as "no credentials" and reopen first-boot setup
> (`/api/auth/setup`) to anyone who can reach the instance. Before
> downgrading, either restore the `credentials.json` backup taken before
> beta.8 first started, or complete setup yourself with a new password
> immediately after the downgrade.

## Highlights

- **The web-login password is hashed.** See [Security](#security).
- **Downloads and WebDAV share one connection budget per server.** The
  downloader and `/dav` together never open more than a server's
  `connections`, and WebDAV playback keeps a reserve. (#286)

## Security

- **Argon2id password hashing (WI-2278, #288).** The web-login password is
  stored as an Argon2id PHC hash and verified in constant time. An existing
  plaintext `credentials.json` is migrated at startup and rewritten
  atomically with mode `0600`. If the migration cannot run, the store fails
  closed: the file is kept and setup stays shut. A corrupt or empty
  credentials file never reopens setup. API-key auth is unchanged.
- **Wrong passwords are delayed per client.** Each wrong password (login,
  HTTP Basic, and the current password in a credentials change) is answered
  after a per-client delay: 0.5 s, doubling up to 30 s, reset after 15
  minutes without a failure. A correct password is never delayed or refused
  and clears the count. IPv6 clients are keyed by /64. Each failure logs
  `Failed web login from <ip>` at warn level. Auth request bodies are
  limited to 16 KiB.
- **Distributed brute force belongs at the proxy.** The per-client delay
  does not stop guessing spread across many addresses, and it does not cap
  connections. Rate-limit `/api/auth/*` at the edge, with Caddy's
  `rate_limit` (caddy-ratelimit module) or fail2ban on the warn line above.
  [docs/CONFIGURATION.md](../CONFIGURATION.md#login-brute-force-protection)
  has a Caddy snippet and a fail2ban filter.
- HTTP Basic auth now runs an Argon2 verify on every request. Clients that
  authenticate heavily should use an API key instead.

## Upgrade notes

- **Back up `credentials.json` before upgrading** (see the rollback warning
  above). Backing up `rustnzb.db` is still recommended; there are no
  database migrations in this release.
- **Reverse-proxy installs: set `general.trusted_proxies`.** Behind a reverse
  proxy every request arrives from the proxy's address, so all clients share
  one failed-login delay until the proxy is listed. Set it to the proxy's
  address or its Docker network, for example
  `trusted_proxies = ["172.18.0.0/16"]`. `X-Forwarded-For` is believed only
  from listed proxies. Leave it empty when rustnzb is reached directly. The
  setting is read on every login, so it needs no restart.
- **WebDAV playback reserve.** `dav.playback_reserve_pct` (default `25`)
  sets the percent of each server's `connections` kept free for WebDAV
  playback and import while WebDAV is enabled. It applies after a restart.

## Connection budget (WI-149, #286)

- The downloader and WebDAV draw from one tiered budget per server
  (playback > import > download > repair), so together they never open more
  than the server's `connections`.
- `dav.playback_reserve_pct` (default 25, rounded up; the downloader always
  keeps at least one connection) is kept free of downloads while WebDAV is
  enabled. Playback may borrow beyond the reserve while the downloader is
  idle.
- WebDAV ingest runs on its own import tier, which shares the WebDAV
  reserve, so imports progress while downloads saturate the server.
- Idle downloader workers close their socket and give their permit back as
  soon as WebDAV is waiting, or after 30 s idle. With WebDAV off they keep
  their sockets as before.
- Repair keeps a 25% floor against downloads while it is active.

## All changes

### Security

- **auth:** the web-login password is stored as an Argon2id hash, migrated
  from plaintext at startup and verified in constant time (WI-2278, #288)
- **auth:** wrong passwords are delayed per client; `X-Forwarded-For` is
  trusted only from `general.trusted_proxies` (WI-2278, #288)

### Changed

- **nntp:** one tiered connection budget per server for the downloader and
  WebDAV, with a WebDAV playback reserve (WI-149, #286)

### Fixed

- **ci:** crate-export resolves inline-table workspace inheritance (WI-168,
  #285)
- **dispatch:** a late-PAR2 test is ordered by a gate instead of timing
  (WI-2286, #287)
