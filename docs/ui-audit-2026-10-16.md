# rustnzb web UI audit — 2026-10-16

Scope: the Angular web UI in `apps/rustnzb/frontend`, checked on the live
instance (sabnzbd.sprooty.com, read-only: every non-GET request except
`/auth/login` and `/auth/refresh` was blocked in the browser) and on a local
production build of this branch served with the repository's `demo/mock-api.js`.
The demo build was only used for populated-queue views, because the live queue
was empty. Its data is fictional and does not match the live instance.

Method: Playwright with Chromium 1248, viewports 1440×900 (desktop) and 390×844
(phone). WCAG 2.2 contrast was computed from the theme tokens in
`src/styles.scss`. A DOM sweep checked accessible names, labels and headings,
and keyboard focus was checked by tabbing through Downloads.

Screenshots are in [`ui-audit-2026-10-16/`](ui-audit-2026-10-16/). `before-*`
files come from the demo build and `live-*` files from the live instance. Live
captures that show provider hostnames were kept out of the repo.

## Integrity verdict

**Fail.** The system is coherent on the happy path: a single token sheet,
consistent panel, card and table grammar, and a clear Operate-mode density. It
does not tell the truth when things go wrong. With every API call returning
500, the shell still shows `● Live`, and the page claims "No servers
configured", "0 jobs" and "Success rate 0%". For a downloader, an error that
looks like real data is the most serious kind of UI defect.

## Findings by severity

Counts: P0 1 · P1 6 · P2 7 · P3 4.

### P0

**[P0] Errors are shown as valid data.**
`live-desktop-error.png`, `live-phone-error.png`
- Location: `src/app/app.ts:480-490` (`pollStatus` has `error: () => {}`);
  queue/history panels in `features/queue/queue-view.component.ts`.
- Impact: when the backend is down or erroring, the user sees "Live", 0 servers
  and 0% success, and may reconfigure servers or re-add jobs that are fine.
- Fix: track an `offline` signal from the status poll and turn the pill into
  `● Offline` (err style). Give each panel an error row ("Couldn't load the
  queue — retrying") instead of its empty-state text. Never render a computed
  rate (0%) from missing data.
- Command: `/impeccable harden`

### P1

**[P1] Primary button text contrast fails WCAG 1.4.3.**
`before-desktop-settings.png` (+ Add server), `before-desktop-groups.png` (Search)
- White on `--accent` `#3b82f6` is 3.68:1. On Midnight, white on `#8b7cf6` is
  3.33:1. Daylight (`#2563eb`) passes at 5.17:1.
- Locations: `styles.scss .btn.primary`, `app.ts:362 .pm-go`,
  `login.component.ts:130`, `statistics-view.component.ts:133`,
  `welcome.component.ts:305`, `settings-view.component.ts:1209`,
  `queue-view.component.ts:725,759,762`.
- Fix: add a `--accent-fill` token (dark `#2563eb` = 5.17:1, midnight `#6a5ae0` =
  5.06:1, light `#2563eb`) for filled surfaces that carry white text, and keep
  `--accent` for text and links.
- Command: `/impeccable colorize` (token only)

**[P1] Form-control boundaries are invisible (WCAG 1.4.11).**
`live-desktop-settings-general.png`, `before-desktop-groups.png`
- Inputs use `--line` `#2a3441` on `--panel2`, which is 1.21:1 (3:1 required). Empty
  fields such as History retention read as dead space.
- Fix: add a `--line-strong` token for control borders (≥3:1 against the
  surrounding panel) and keep `--line` for dividers.

**[P1] Focus indication is inconsistent and partly removed.**
`live-desktop-focus-tab6.png`
- Buttons and links fall back to Chrome's 1px `auto` ring (white, thin, and
  clipped by the top bar's `overflow-x:auto`). Text inputs set `outline:none` in
  8 places (`app.ts:359`, `login.component.ts:124`, `groups-view:250`,
  `group-browser-dialog:57`, `queue-view:910,937,1068`, `welcome:337`), so the
  only focus cue is a border-colour change from `--line` to `--accent`. No
  component uses `:focus-visible` except queue-view.
- Fix: one global `:focus-visible` ring (2px `--focus`, 2px offset; box-shadow
  for inputs so component `outline:none` doesn't kill it).

**[P1] Phone layout breaks on every main view.**
`before-phone-downloads.png`, `before-phone-settings.png`, `live-phone-logs.png` (local only)
- `.cards4`/`.cards3` keep 4 and 3 columns at 390px, so values wrap mid-number
  and Disk Free is clipped. The settings sidebar stays a 220px column, which
  leaves about 100px for content. The `.form` grid keeps its 180px label column.
  The queue table squashes its headers into overlapping text ("PROGRESS"
  overprinting). Log lines wrap one character per line. Upload NZB, Pause and the
  status pills are pushed off-screen in a horizontally scrolling nav with no
  overflow cue.
- Fix (low risk): collapse card grids to 2 then 1 column, stack the settings nav
  above content, and make `.form` a single column below 640px. Give the log line
  column `min-width:0` with `overflow-wrap:anywhere` on the message only.
  (Larger work: a card layout for queue rows on phone, and a compact top bar
  with an overflow menu. That needs a design decision; see Open decisions.)
- Command: `/impeccable adapt`

**[P1] Blank screen while the first API response is pending.**
`live-desktop-loading.png`
- With the API delayed by 8s, the whole viewport stays `--bg` with no shell,
  spinner or text. On a slow NAS the app looks dead.
- Fix: render the shell immediately and add skeleton or "Loading…" rows in the
  panels.
- Command: `/impeccable harden`

**[P1] Contradictory numbers between top bar and cards.**
`live-desktop-downloads.png` (local only)
- The pill shows `0 B free` while the Disk Free card shows `738.6 GB`, because
  `/status.disk_space_free` and the queue view's disk source disagree on the
  live instance. This is a data bug surfaced by the UI. Not fixed here: it needs
  backend investigation.

### P2

- **[P2] History filters have no accessible names.** The filter text input,
  three `<select>`s and the select-all checkbox are unlabeled (DOM sweep). Add
  `aria-label`s. `queue-view.component.ts` history toolbar.
- **[P2] No `h1`; heading levels skip.** The page title "Downloads" is `h2`,
  "History" is `h2` inside the Downloads page, and panel titles are `h3`. Make
  the route title `h1`.
- **[P2] Type scale has nine sizes in the shared CSS** (10, 11, 12, 13, 14, 15,
  18, 22px, plus 13.5 in components), and 10–11px is used for meaningful text
  (`.article-failures` 10px red, `.pill` 11px, `.tag` 11px, form help 11px).
  Concurrent-jobs help is 11px next to 14px siblings
  (`live-desktop-settings-general.png`). Collapse to the scale below with a 12px
  floor for content.
- **[P2] Theme leakage.** `.s-dl`, `.s-q`, `.s-pp`, `.s-paused`, the
  `.pill.ok/.warn/.err` borders, the `.tag.*` borders and `.btn.primary:hover`
  are hard-coded dark-theme hex, so they look wrong on Daylight. `.s-paused`
  (`--mute` on `#2a3441`) is 4.29:1 and fails.
- **[P2] Queue table column rhythm.** NAME is centred over left-aligned names,
  PAUSE and DELETE are separate one-icon columns, and progress text wraps
  ("5.4 GB / 8.0 / GB") (`before-desktop-downloads.png`). Left-align text
  headers, merge row actions into one column and widen progress.
- **[P2] Settings help text is squeezed into the label column.** In Debug
  logging, a 6-line paragraph sits in the 180px label column
  (`live-desktop-settings-general.png`). Help belongs under the control
  (`.form .help` already exists).
- **[P2] Pipeline stepper overflows on phone.** It needs horizontal scroll or a
  vertical layout (`before-phone-downloads.png`).

### P3

- **[P3] Button sizes drift.** There are four heights (`.btn`, `.btn.sm`,
  search-bar 10px padding, settings "Save" small). Settings rows put a small
  Save next to a 38px input.
- **[P3] Implementation detail in the main UI.** "SQLite FTS5 over
  XOVER-fetched headers" and "tracing subscriber · following" are developer
  copy. Move them to tooltips or About.
- **[P3] The "Live" pill has two meanings** (running vs paused, not connection
  health). Once Offline exists, keep the three states distinct.
- **[P3] Scrollbar thumb hover `#3a4656` is hard-coded.**

## Positive findings

- There is one token sheet (`styles.scss`) with three complete themes, and
  components consume `var(--…)` almost everywhere.
- The Operate-mode density fits the domain: compact tables, tabular numbers and
  panel grammar are used consistently across views.
- The top bar's icon toggles have proper `aria-label` and `aria-pressed`, and
  the pause menu uses `aria-haspopup` and `aria-expanded`.
- The queue empty state gives a next action ("Click + Upload NZB…").
- `lang="en"` and a `<main>` landmark are present. The DOM sweep found no
  unnamed buttons.

## Proposed design tokens

Add these to `:root` in `styles.scss`. Override the colour rows per theme.

```scss
:root {
  /* colour — new roles */
  --accent-fill: #2563eb;      /* filled bg under white text (≥4.5:1). midnight #6a5ae0, light #2563eb */
  --line-strong: #5f6f84;      /* form-control borders (≥3:1). midnight #5d72a3, light #7a8496 */
  --focus:       #60a5fa;      /* focus ring (6.7:1 on panel). midnight #a89bff, light #2563eb */
  --focus-ring:  0 0 0 2px var(--bg), 0 0 0 4px var(--focus);

  /* type scale (px, 1.2-ish) — 12 is the floor for content */
  --fs-xs: 12px;   /* meta, table headers, pills, tags, help */
  --fs-sm: 13px;   /* table body, secondary */
  --fs-md: 14px;   /* body, controls */
  --fs-lg: 18px;   /* page titles (h1) */
  --fs-xl: 22px;   /* stat values */

  /* spacing (4px base) */
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-5: 24px; --sp-6: 32px;

  /* radius / control */
  --radius-sm: 4px; --radius: 6px; --radius-lg: 8px;
  --control-h: 34px;           /* one height for inputs, selects and .btn */
}
```

Status-pill colours should become per-theme tokens (`--s-dl-bg/--s-dl-text`,
and the same for queued, post-processing and paused) instead of literals.

## Open decisions (for the operator)

- **Phone navigation pattern**: either a compact top bar with an overflow menu
  for Upload, Pause and Sign out, or a bottom tab bar. This affects every view.
  Recommendation: an overflow menu, which is less code and keeps one shell.
- **Queue on phone**: card rows or a horizontally scrolling table.
  Recommendation: card rows, because a 10-column table can't fit at 390px.
- **Developer copy** (FTS5, tracing subscriber): keep it for power users or move
  it to About.
- **Disk-free mismatch**: needs a backend owner. The UI fix is out of scope.
